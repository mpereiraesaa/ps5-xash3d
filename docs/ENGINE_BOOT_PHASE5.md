# Xash3D engine boot — Phase 5 gate 1

Phase 5 is the platform layer: everything the engine needs that is not
drawing. Its first gate boots the real Xash3D FWGS engine on the PS5 in
dedicated mode, so filesystem, memory, threads, time, sockets and the three
measured libc shims are exercised by the engine itself instead of by
synthetic probes. Nothing is rendered; every proof arrives as `ps5log/1`
telemetry and captured console output.

## What is built

`make engine-boot-native-release` (`xash/build_engine.sh`) compiles, with the
pinned Prospero toolchain and no waf:

| Part | Sources | Notes |
| --- | --- | --- |
| Engine | `engine/common`, `imagelib`, `soundlib`, `server`, `http`, `public`, `platform/posix` (minus `sys_posix.c`, crash handlers and `lib_posix.c`), `platform/misc/lib_static.c`, `library_suffix`, bundled bzip2 | `XASH_DEDICATED=1 XASH_STATIC_LIBS=1`, `TIMER_POSIX`, `MSGBOX_STDERR` |
| `filesystem_stdio` | `filesystem/*.c`, `VFileSystem009.cpp` | Relocatable module, only `lib_filesystem_stdio_exports` stays global |
| `server` | hlsdk-portable `dlls/`, `pm_shared`, OpenBSD `strl*` | Same treatment; exports `GiveFnptrsToDll`, `GetEntityAPI`, `GetEntityAPI2` |
| PS5 backend | `xash/platform_ps5/sys_ps5.c`, `boot_ps5.c` | Clock, sleep, SIGTERM, `__assert`, `getpwuid`, `dladdr`, `__dso_handle`, bounded quit, `main` |

The static module tables are generated by
`xash/tools/generate_static_library_tables.py` from `xash/exports/*.txt`,
mirroring the engine's `xshlib.py`: `COM_LoadLibrary("filesystem_stdio")` and
`COM_LoadLibrary("server")` resolve through `lib_static.c` without any loader.
Modules are linked with a host `ld -r` and reduced with
`llvm-objcopy -G lib_<name>_exports`, so the hlsdk `pm_shared` copy never
collides with the engine's own symbols. The SDK's lld is not used for the
relocatable step because it emits one relocation section per COMDAT group and
the final link rejects that.

The three libc gaps measured in the laboratory symbol probe are closed in
`sys_ps5.c`: `__assert` prints and aborts, `getpwuid` returns a fixed `ps5`
identity for the machine-id salt, and `dladdr` returns failure so `whereami`
falls back. Everything else the engine imports comes from the SDK stubs
(`libSceLibcInternal`, `libkernel`, `libkernel_sys`); the linked title has 162
imports and no unresolved symbol.

## Boot contract

`main` initializes `ps5log/1` with stdio capture, so every console line is a
RAW transcript line, then:

1. picks the first writable base directory of `/download0/xash3d`,
   `/data/homebrew/<title>/xash3d-rw`, `/tmp/xash3d`, `chdir`s into it and
   exports `XASH3D_BASEDIR` (the engine's `FS_DetermineRootDirectory` reads
   the environment first, then `getcwd`);
2. emits `XASH_BOOT schema=1 slice=engine-boot mode=dedicated ... engine=<7hex>
   hlsdk=<7hex> rodir=/app0/xash3d basedir=<dir> gamedir=valve map=<map>
   gate_seconds=<n> rodir_present=<0|1>`;
3. calls `Host_Main` with `-dev 2 -console -log -rodir /app0/xash3d -game valve
   +map <map>`;
4. `PS5_XASH_GATE_SECONDS` after the first host clock read on the main thread
   the backend prints `PS5_XASH_GATE_TIMEOUT seconds=<n> action=quit` and
   queues `quit`, so the engine leaves through its own shutdown path;
5. emits `XASH_EXIT result=<n>`, closes telemetry with
   `BYE reason=xash-engine-boot-complete` and calls `_exit(0)`.

Game data is read-only under the title: stage a private Half-Life `valve/`
directory with `XASH_GAME_DATA=/private/path` and the build copies it to
`dist/engine-boot/<title>/xash3d/valve`. It is never committed; `.bsp` and
`.wad` files are ignored repository-wide.

## Hardware acceptance

Deploy `dist/engine-boot/PPSA99996/` as the title directory (the `xash3d/`
tree included), reload the mount, launch through the laboratory helpers and
watch `ps5logd`. The run passes when
`tools/validate_engine_boot_evidence.py <manifest> --engine-commit <7hex>
--hlsdk-commit <7hex> --map c1a0` accepts it, which requires:

- clean `HELLO`/`BYE` with title `PPSA99996`, app `xash3d-engine`, no
  sequence gaps, no `ERROR` records, transcript hash matching the manifest;
- exactly one `XASH_BOOT` with the built engine/hlsdk commits, a selected base
  directory, `rodir_present=1` and a positive `gate_seconds`;
- console proofs: `filesystem_stdio successfully loaded`,
  `Spawn Server: <map>` and the `PS5_XASH_GATE_TIMEOUT ... action=quit` line;
- no `Host_Error:`/`Sys_Error:` console lines and `XASH_EXIT result=0`.

Default gate length is 90 seconds (`XASH_GATE_SECONDS`), long enough for the
server to spawn `c1a0` and run its frame loop; set `0` for an open-ended
session closed by the operator.

## Host verification performed

- `make test` and `make audit` pass with the two new Python suites; the audit
  treats declared submodule trees as pinned upstream code.
- The title builds reproducibly on the host: engine `9aa39ad`, hlsdk
  `e277ffa`, both module objects expose exactly one global symbol, and the
  final ELF defines `libs`, `lib_filesystem_stdio_exports`,
  `lib_server_exports`, `Host_Main` and `main`.

## Not yet proven on hardware

This gate has not run on the console yet. Open questions it is designed to
answer: `getcwd`/`/download0` writability from a title, `pthread_create` and
BSD sockets from a title, engine heap growth against the ~432 MiB anonymous
ceiling before the direct-memory allocator lands, hlsdk static initializers
under the boilerplate CRT, and whether `whereami` needs a `dladdr` that
returns the executable path.
