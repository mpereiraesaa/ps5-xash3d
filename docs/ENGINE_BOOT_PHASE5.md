# Xash3D engine boot — Phase 5 gate 1

Phase 5 is the platform layer: everything the engine needs that is not
drawing. Its first gate boots the real Xash3D FWGS engine on the PS5 in
dedicated mode, so filesystem, memory, threads, time, sockets and the three
measured libc shims are exercised by the engine itself instead of by
synthetic probes. Nothing is rendered; every proof arrives as `ps5log/1`
telemetry and captured console output.

## What is built

`make engine-boot-native-release` (`xash/build_engine.sh`) compiles, with the
pinned Prospero toolchain and no waf:

| Part | Sources | Notes |
| --- | --- | --- |
| Engine | `engine/common`, `imagelib`, `soundlib`, `server`, `http`, `public`, `platform/posix` (minus `sys_posix.c`, crash handlers and `lib_posix.c`), `platform/misc/lib_static.c`, `library_suffix`, bundled bzip2 | `XASH_DEDICATED=1 XASH_STATIC_LIBS=1`, `TIMER_POSIX`, `XASH_MESSAGEBOX=99` (own message box) |
| `filesystem_stdio` | `filesystem/*.c`, `VFileSystem009.cpp` | Relocatable module; exports `GetFSAPI`, `CreateInterface` |
| `server` | hlsdk-portable `dlls/`, `pm_shared`, OpenBSD `strl*` | Exports `GiveFnptrsToDll`, `GetEntityAPI`, `GetEntityAPI2` plus every `LINK_ENTITY_TO_CLASS` symbol the module defines (251 on this pin), because `SV_GetEntityClass` resolves map classes through `COM_GetProcAddress` |
| PS5 backend | `xash/platform_ps5/{boot,sys,fs,mem}_ps5.c` | Entry, clock, signals, libc shims, path layer, allocator router, console sink |

The static module tables are generated by
`xash/tools/generate_static_library_tables.py`, mirroring the engine's
`xshlib.py`: `COM_LoadLibrary("filesystem_stdio")` and
`COM_LoadLibrary("server")` resolve through `lib_static.c` without any loader.
The server export list is produced at build time from the `LINK_ENTITY_TO_CLASS`
scan of hlsdk intersected with the symbols the compiled module defines.
Modules are linked with a host `ld -r` and reduced with
`llvm-objcopy -G lib_<name>_exports`, so the hlsdk `pm_shared` copy never
collides with the engine's own symbols. The SDK's lld is not used for the
relocatable step because it emits one relocation section per COMDAT group and
the final link rejects that.

## What the sandbox does on FW 12.02 (measured)

Every item below was observed from this title on the console and shaped the
backend; none was documented by the foundation.

| Call | Result | Backend response |
| --- | --- | --- |
| Descriptors 0-2 at start | Closed; `dup2` onto them fails with `EPERM` | stdio is never redirected; console goes through a `write()` shim |
| `getcwd()` (libSceLibcInternal) | `SIGSEGV` inside the library | `getcwd`/`chdir`/`realpath` shims keep a virtual working directory |
| `chdir()` | `EPERM` for every path, `/app0` included | `filesystem_stdio` addresses its root as `./`; the path layer resolves relative paths against the virtual cwd and forwards to `sceKernel*` |
| `access()` | `EPERM` on `/download0` while `open`/`write` succeed | `access` shim answers with `stat` |
| `opendir()` (libc) | `EPERM` everywhere | Own `opendir/readdir/closedir` over `sceKernelOpen(O_DIRECTORY)` + `sceKernelGetdents` (FreeBSD 9 dirent layout) |
| `getdents` on `/app0` | `EINVAL`; `/download0` lists normally | The build writes `xash3d/.dirindex` (818 entries here) and the image is listed from it |
| `/download0` | Present, `mkdir` and file creation work (`downloadDataSize` 256) | Engine root directory; `/app0/xash3d` is `-rodir` |
| `/temp0` | Absent (`ENOENT`) | Probed, never assumed |
| libc `malloc` | Largest success 8 MiB, 16 MiB fails; the map's 21.25 MiB packet-entity pool failed | lld `--wrap` of `malloc/free/realloc/calloc`: requests ≥ 256 KiB go to anonymous `mmap`, tracked in a registry (peak 32 MiB in the passing run) |

| `getaddrinfo`/`gethostname` | Would import `libScePosixForWebKit`; a NULL fault was traced to that path | Local shims: numeric IPv4 resolves, names fail cleanly |
| `sockets`, `bind`, `sendto`, `poll`, `pthread_create`, `clock_gettime` | Work | Used unchanged |

## Boot contract

`main` initializes `ps5log/1`, installs a signal reporter (signal, fault
address, program counter and stack words relative to `main`), loads the
directory index, probes the volumes and then:

1. selects `/download0/xash3d` when a file can be created there, exports
   `XASH3D_BASEDIR` and sets the virtual cwd (the engine's
   `FS_DetermineRootDirectory` reads the environment first); falls back to the
   read-only image otherwise and says so;
2. emits `XASH_BOOT schema=1 slice=engine-boot mode=dedicated ... engine=<7hex>
   hlsdk=<7hex> rodir=/app0/xash3d basedir=<dir> gamedir=valve map=<map>
   gate_seconds=<n> rodir_present=<0|1>`;
3. calls `Host_Main` with `-dev 1 -console -log <basedir>/engine.log -rodir
   /app0/xash3d -game valve +map <map>`;
4. `PS5_XASH_GATE_SECONDS` after the first host clock read on the main thread
   the backend prints `PS5_XASH_GATE_TIMEOUT seconds=<n> action=quit` and
   queues `quit`, so the engine leaves through its own shutdown path;
5. emits `XASH_EXIT result=<n> ... large_alloc_*`, closes telemetry with
   `BYE reason=xash-engine-boot-complete` and calls `_exit(0)`.

Console lines are assembled into whole lines and stripped of ANSI escapes
before entering the stream, so RAW lines never split a structured record.

Game data is read-only under the title: stage a private Half-Life `valve/`
directory with `XASH_GAME_DATA=/private/path` and the build copies it to
`dist/engine-boot/<title>/xash3d/valve` and indexes it. The passing run used a
40 MB server-side subset: `liblist.gam`, the root `.cfg/.lst/.txt` files,
`gfx.wad`, `maps/c1a0.bsp`, `models/`, `sprites/`, `events/`, `scripts/` and
`sound/sentences.txt`. `gfx.wad` is required even in dedicated mode. Nothing
of it is committed; `.bsp` and `.wad` files are ignored repository-wide.

## Hardware acceptance

Deploy `dist/engine-boot/PPSA99996/` as the title directory (the `xash3d/`
tree and its `.dirindex` included), reload the mount, launch through the
laboratory helpers and watch `ps5logd`. The run passes when
`tools/validate_engine_boot_evidence.py <manifest> --engine-commit <7hex>
--hlsdk-commit <7hex> --map c1a0` accepts it, which requires:

- clean `HELLO`/`BYE` with title `PPSA99996`, app `xash3d-engine`, no
  sequence gaps, no `ERROR` records, transcript hash matching the manifest;
- exactly one `XASH_BOOT` with the built engine/hlsdk commits, a selected base
  directory, `rodir_present=1` and a positive `gate_seconds`;
- console proofs: `filesystem_stdio successfully loaded`,
  `Spawn Server: <map>` and the `PS5_XASH_GATE_TIMEOUT ... action=quit` line;
- no `Host_Error:`/`Sys_Error:` console lines and `XASH_EXIT result=0`.

Default gate length is 90 seconds (`XASH_GATE_SECONDS`); set `0` for an
open-ended session closed by the operator. Note that ftpsrv serves signed
files back as their decrypted ELF image with the last 512 bytes rewritten, so
an upload is verified against `build/engine-boot/eboot.elf` by prefix.

## Host verification performed

- `make test` and `make audit` pass with the two new Python suites; the audit
  treats declared submodule trees as pinned upstream code.
- The title builds reproducibly on the host; both module objects expose
  exactly one global symbol; the interposed libc symbols are kept out of the
  dynamic symbol table by `xash/platform_ps5/app-symbols.map`.

## Iteration record

Nineteen hardware launches closed the gate. In order they exposed: no stdio
capture (`dup2` `EPERM`), the `getcwd` fault, the missing `CreateInterface`
export, `chdir` `EPERM`, the unlistable image (`gfx.wad` and game folders
invisible), the libc heap ceiling, the `getaddrinfo` fault, the blocking
UDP socket that kept the gate from firing, the entity export table, ANSI
escapes gluing a structured record to a console line, and finally a
`PS5_XASH_GATE_SECONDS` definition that had not reached the backend. Each
answer is a shim or a build step above; the engine sources are untouched.
